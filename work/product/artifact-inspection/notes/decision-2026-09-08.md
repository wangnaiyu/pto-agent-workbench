# 分析启动与对话布局修复决定

- 日期：2026-09-08
- 记录者：Codex，根据用户真实体验与逐项反馈整理
- 状态：accepted（产品设计）；尚未实现或重新验收

## 背景

真实 Web 使用中，从 dependency Viewer 点击“AI 分析”后，首次发送只进入普通用户文本，
没有把 `pto-artifact-analysis` receipt、Record revision 和固定 Skill 绑定到模型首步。第二次
尝试仍未走正式门禁，Agent 改用通用 Shell 手动复算。另有自定义“实验”Tab 不随 DSH 对话
正文宽度变化，形成内容越界。

## 决定

1. 按钮保持“AI 分析”。点击后退出全屏 Canvas，进入视觉上的新会话草稿页；发送前不创建
   Session、不调用模型。
2. 输入区只显示规范 `/skill dependency-redundancy`、`@deps.json` 和短 Prompt：
   “分析冗余依赖，给出结论、证据、限制和建议。”点击动作在语义上等价于手动选择 Skill 与文件。
3. Record/数据集名称和 revision 默认不显示；provider、action、tool tuple、绝对路径与完整上下文
   也不在输入区展开。上述事实继续结构化携带，可在引用详情或审计记录查看。
4. 可见 `/skill` 与 qualified Skill attachment 必须收敛到同一次固定版本 Skill 调用，不重复注入，
   也不因 UI 简化而降级成只按名称解析。
5. 每次从 Viewer 有意点击“AI 分析”产生新 launch，发送后产生新 Session；同 launch 的失败重试
   复用同一 Session。双击合并为一次 activation，未发送草稿不得静默覆盖。
6. first-send 是不可降级事务：Session 创建、Host admission、receipt/Skill 绑定、prompt 发送按序
   完成。缺 receipt 不发送普通 prompt，不用通用 Shell 手动复算冒充正式结果。
7. DSH 原生左右正文宽度手柄保留不改；具体“实验”Tab 是工作台扩展，其 Dashboard 应遵守
   `--dsh-chat-content-width`。修复未通过前可隐藏该 Tab，不扩张为 DSH 核心布局模式改造。

## 影响

本决定替代 2026-09-04 后关于“Viewer dependency 分析 first-send 当前已闭环”的状态描述，
不否定同一任务已经验证的 Profile、纯查看、dependency/memory/IR adapter 和官方工具离线结果。
实施与新证据由 [回归修复任务](../../../archive/tasks/2026-09-08-artifact-analysis-launch-repair/README.md)
维护；旧归档保留为历史，不回写成当前政策。
