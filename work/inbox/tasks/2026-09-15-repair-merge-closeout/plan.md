# 收口计划

1. 复核两仓实时 refs、恢复点、远端目标和既有验证；记录 outgoing scope。验收：基线/恢复条件明确，无未知工作树变更。
2. 正常推送两仓最终工作分支与必要恢复 refs，分别创建互链 PR。验收：远端 SHA 匹配、PR 目标正确、描述含阶段提交/验证/known issues。
3. 审查 harness PR 的实际 CI、审查状态和合并门禁；只用 merge commit 合入 fork master。验收：远端 master 包含所有阶段 SHA，记录 tree 与候选一致性。
4. 在工作台独立维护提交记录 harness 最终 SHA，更新 PR 配对，满足门禁后 merge commit。验收：工作台 main 包含修复及配对记录。
5. 同步两仓本地主分支，保存含最终两仓 SHA 的 annotated tags；审计分支独有提交，删除已包含的普通 PR/阶段分支，保留 P0/P1、savepoint、升级前后恢复 refs 和证据。完成报告/整包归档经正常文档 PR 收尾；最终 tags 以最后主分支为准。验收：本地/远端主分支相同、工作树干净、记录和恢复点完整。

既有失败逐项归因，不当成绿色；新失败或必需门禁无法满足即阻塞对应合并，不降规则、不使用 admin bypass。相同已验证源码不因提交/推送机械重跑通过的测试；合并引入变化时重选必要检查。
