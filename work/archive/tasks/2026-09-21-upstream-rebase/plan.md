# 执行计划

1. P1 固定基线：核验两个远端、固定 upstream commit，审计版本/差异/持久化变化，保存旧 master，确定验证面。完成标准为可恢复的 OID 和重放清单。
2. P2 隔离 rebase：独立候选 checkout 重放 fork 提交，逐项处理冲突和消费者适配；用 range-diff 核验无意外丢失。完成标准为候选可构建及完整迁移账本。
3. P3 兼容验证：锁定安装、完整构建、适用门禁、PTO 与持久化/GUI/浏览器、真实 patch 的隔离实例检查；失败须修复或同版本 upstream 归因。完成标准为风险相关检查通过且限制明确。
4. P4 安全更新：重新观察远端，保存恢复 ref；精确 lease 更新 master，验证远端及 CI，安全同步原 checkout。完成标准为目标一致且没有覆盖并发提交。
5. P5 配对收口：回写正式文档与报告、结构/密钥检查、外层提交，创建同 JSON annotated 配对 tags；核验两仓远端并整包归档。完成标准为可追溯三元 SHA 和干净工作树。
