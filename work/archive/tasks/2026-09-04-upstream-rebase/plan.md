# 实施顺序

1. P0 保存与定界：记录双仓基线，创建本地 pre-rebase 保存分支，fetch `upstream` 与 `origin`，核对远端未移动和实际提交差异。
2. P1 历史重放：将 fork `master` rebase 到本次 `upstream/master`，逐项解决冲突；保留 PTO 行为，记录被上游吸收或需适配的差异。
3. P2 验证：按受影响面运行聚焦测试、类型/构建或上游要求的必要检查；区分通过、失败与既有问题。
4. P3 更新 fork：确认 `origin/master` 仍在预期旧值后使用 `--force-with-lease` 推送；核对远端与本地一致。
5. P4 收尾：回写当前架构/踩坑和任务证据，完成报告并归档任务；外层提交或推送仅在另行授权后执行。

每个阶段按任务流程更新开始/完成 checkpoint。任一未提交改动、远端意外移动或无法确认的冲突都会停止覆盖性操作。
