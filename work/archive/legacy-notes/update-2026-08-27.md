## PTO 业务 Skills：联合边界复核

- 模型只允许 plan/get/list，不能直接 authorize 或提交 executor 状态。spike 的 private Host handler 只能模拟 identity、authorization 与 execution transition，全部标记 `spike-simulated`。

## PTO 可信实验执行准入切片

- `ctx.approval.requestDecision()` 在成对 audit event 提交后返回 service-issued approval id 与 outcome，使 experiment receipt 无需从 Session history 恢复 id。
- `ctx.fs.reserveDirectory()` 在 local/sandbox/E2B provider 上实现相同的 fail-if-present 空目录原子占用；parent 必须已存在，竞争只有一个 winner。
- `PtoExperimentStore.execute()` 为 Host-only 单一复合路径：planned revision 校验 → Workspace/path/baseline/candidate 检查 → clean Git 与 Python/PyPTO 固定探针 → 精确用户审批 → 二次检查 → 原子 reservation → 持久 `running` → 执行 → recognized terminal run。
- 模型仍只能 plan/get/list；不存在 bind/authorize/begin/complete 工具。workload 在 `danger-full-access` 下运行已审批 command，并获得 Host 注入的精确 output path；不持久 stdout/stderr 内容。
- exit zero 仍必须通过 PTO run recognizer；其他 exit/signal/timeout/sandbox/infrastructure/cancellation 为 terminal failed/cancelled。Host restart 将遗留 foreground `running` 恢复为 failed。
- 已知 fail-closed 残留：reservation 成功但后续 durable put 失败时可能留下空 orphan candidate，但 workload 不会开始，且 path 不可静默复用。

后续优先级转为 app-owned metric identity/collection adapter，然后是 comparison Host 原语；evidence-gated UI 仍最后消费同一 registry/capability 事实。这两个 Host 能力已由同日后续切片完成，见下节。

## PTO app-owned 指标采集与比较切片

### 实现

- `PtoExperimentStore.execute()` 在 recognized L2 run 完成后运行固定 `pypto-chip-swimlane-makespan-v1` adapter，只读取该 registered run 中当前的 `dfx_outputs/chip_swimlane_records.json` 和 `compiled_meta.json`。
- Python probe 复用 PyPTO 官方 `simpler_setup.tools.swimlane_converter.read_perf_data()`，以最晚 finish 减最早 dispatch 得到单次 L2 `device-dispatch-makespan` 微秒值，不复制上游 cycle/join 公式。
- 持久 schema 升为 v2，为 actual run 记录 metric definition/value、task identity、hardware identity、artifact digest 与 source/environment/command lineage。public view 继续移除 filesystem target key。
- 新增 `PtoExperimentStore.compare()` 与模型工具 `pto_experiment_compare`。它只比较同一 Workspace 中另一 completed experiment 的 registered actual run，并要求 metric/task/hardware/environment/command/source-root/committed Git diff 七个维度全部匹配。

### 设计判断

- missing current artifact 记为 `not-observed`，格式错误、越界或超限记为 `invalid`；二者都不改写 recognized successful run 的 completed 状态，但会 fail closed 地阻止比较。
- 首版不猜测 legacy `l2_swimlane_records.json` 或 L3 dispatch tree，也不自动重跑 workload。chip-swimlane 输入默认最大 64 MiB，`compiled_meta.json` 固定最大 1 MiB。
- 任一 identity 缺失或不匹配时返回 `incomparable` 且 `delta: null`。全部匹配时才计算 `candidate - baseline` 与方向；因没有用户所有的 threshold、repetition 和 significance rule，结果仍为 `inconclusive`/`needs-user-confirmation`。
- comparison 是从持久观测按需派生的纯计算，不是另一 lifecycle transition，也不持久二次结果。

### 验证结果

- executor/comparison 测试覆盖 collected metric、metric 缺失仍 completed、unowned baseline 不可比、非空 committed change 上的 -20% admitted delta，以及 task identity 变化时拒绝 delta。
- 包级 typecheck、contract lint、generated catalog/type equivalence、双语配对、doc-sync 与 Host build 作为整体门禁。

### 后续动作

- 第七阶段下一个主线切片转向 evidence-gated details/overlay/comparison UI，只消费同一 registry/capability 事实。
- L3/legacy adapter、多次采样、variance 与 threshold/significance policy 保持显式延后，不隐式扩大 v1 adapter。

## PTO evidence-gated comparison UI 切片

### 实现

- `ui-tool` 新增 session-scoped keyed details 子槽 `tool.result.detailview`；整面板 single slot 仍由通用 Tool UI 占用，未知工具继续走原 fallback。
- 新增纯 Client package `@deepseek-ai/dsh-client-ui-pto-experiments`，为 `pto_experiment_compare` 提供专用 transcript row 和 details 内容，并由 PTO profile 显式启用。
- details 并列展示 baseline/candidate、七个 comparison identity、Host 返回的限制原因；只有通过 evidence gate 的 `inconclusive` 结果才展示 delta。
- UI parser 校验闭合 schema，并复核 absolute、relative 与 direction 是否和两边 app-owned metric 一致；不一致或 malformed success 一律显示“依据不可用”。

### 设计判断

- UI 只消费冻结的 durable Tool result，不重新请求 Host、不读取 artifact、不维护 experiment registry 副本，因此 replay 与错误隔离保持确定。
- `improved` 只是较低 makespan 的算术方向，不能在 UI 中升级为 supported、success 或已验收；`needs-user-confirmation` 保持显式。
- 本切片不使用 `shell.overlay`。单次 comparison 的行→details 已形成最小闭环；全局 overlay 需要跨 call 聚合或实验列表的真实 projection/controller，不能先用 transcript JSON 拼成隐式状态源。
- 新 keyed slot 是结构性 seam，已同步写入 decision 与 `ui-tool` 契约；PTO 业务包只按 wire tool name 注册，不接管通用 details 面板。

### 验证结果

- 新包与 `ui-tool` package typecheck 通过；完整 Client TypeScript aggregate 通过。
- comparison model 单测覆盖 admitted -20% delta、篡改百分比 fail-closed、`incomparable + delta:null` 和 Tool error 隔离。
- 后续整体门禁以生成目录、双语配对、Client bundle purity、package invariants 与 PTO/Tool UI 回归为准。

### 后续动作

- 下一 UI 切片先验证是否存在跨 experiment/call 的 dashboard 需求；只有需要主动打开、列表聚合或持续刷新时才设计 overlay projection 与 controller。
- L3/legacy adapter、多样本统计、threshold/significance policy 继续留在 Host evidence 层，不由 Client 扩写。
