## 新会话输入框 `+` 的草稿能力目录：Host 静态目录

### 变更

- 新增 `harness/packages/host/composer-catalog`，提供只读 Remote `composerCatalog.listDraft({ workspaceId?, agentPreset? })`，并装配进 Web Host bundle 与 Client Remote facade。
- 命令注册定义新增可选技术 `provider`；`listDiscoveryForScope()` 返回最终 winner 的 descriptor、`global | scoped` layer 与 provider，不把 handler、scope key 或内部路径放进 wire。
- Host 目录按可信 `providerOrigins` 配置投影 `DSH`、`Agent`、`PTO`、`User`、Workspace 名称和插件名称；未知插件降级为 `Plugin`。
- Skill 目录只保留 `userInvocable` winner，同时返回 `modelInvocable`；默认顺序为 User、PTO、Workspace、DSH、Plugin，再按来源标签与名称稳定排序。
- 未分组查询使用真正的 `cwd: undefined` 并过滤 project source；Workspace 查询由 Host 注册表解析路径和显示名称，并可读取 preset 隔离 realm 的 Skills service。
- 响应包含内容哈希 `revision` 与局部错误；description 在 Host 侧限制为 1000 字符。首版不发送图标内容，只保留可选 `iconId` 协议位置。

### 边界与判断

- 本阶段只建立 Host 静态事实源，不实现 Client 菜单、`/skill <name>` 语法或首次发送再校验。
- `bundled` 继续只是技术来源，不自动等于 PTO；下一阶段由 PTO profile/provider 显式把本仓库 `skills/` 声明为 `PTO`。
- 当前 Skill registry 对 provider 失败只暴露 `complete=false`，因此 seam 能保留成功条目并给出 Skills 区域级局部错误；待底层提供 provider 级诊断后再细化到具体来源标签。
- 静态目录使用内容哈希 revision 满足当前 generation 边界；是否增加推送失效事件留到 Client source 引入真实缓存时决定。

## 新会话输入框 `+` 的草稿能力目录：首次发送再校验

### 变更

- Host `composer-catalog` 新增 `composerCatalog.listSession({ sessionId })`，从已创建 Session 的有效 Agent scope、Workspace 归属和隔离 Skill registry 返回与草稿同形的 Commands/Skills 最终目录；未 attach 时使用持久化 preset 的 standing scope，不恢复冷 Agent。
- Session `ui-commands` 与 `ui-skill` 优先使用正式目录，并将行尾来源统一为 `DSH`、`Agent`、`PTO`、`User`、Workspace 名或插件名；Commands 保持无标题，Skills 保持 `Skills` 分区，同名项分区共存。
- 草稿首次发送实体化 Session 后、提交 prompt 前，`ui-composer-catalog` 拉取 `listSession` 并对比已观测的草稿条目：能力消失、origin 改变、Skill 调用策略改变或新出现的同名 Command/Skill 冲突都会拒绝。
- 准入拒绝后，捕获的文本与图片保留在已经可见的真实 Session composer，页内显示错误，不发送模型 prompt。
- 公开 `session.prompt` 在持久化之前使用共享 parser 解析所有规范 `/skill <name>`，按精确 Session Skill registry 和 `userInvocable` 独立准入；该边界同时保护 Web、CLI 和 ACP 手输路径。

### 边界与判断

- 首发校验会先物化唯一空白 Session，再读取它的最终目录；失败不会落账用户消息或启动 Agent turn，该 Session 也不会作为已开始会话出现在导航中。
- origin 和冲突的“变化”只能对比 Client 已经拉取过的草稿快照。对从未打开菜单的纯手输文本，正式目录仍会检查规范 Skill 当前是否存在且可调用，但不伪造不存在的历史 origin。
- `session.prompt` 的 Host 准入是最后安全边界；Client 对比是为了给首发用户更完整的变化诊断，不取代 Host 复核。pre-step 只保留正文加载与注入责任。

### 验证结果

- 共享 Skill parser、Host 正式目录、`session.prompt` 准入、Session Commands/Skills source 和草稿首发对比的定向单元／集成测试通过。
- Host 与 Client 相关 TypeScript project references 通过；Host Remote artifact 已生成 `composerCatalog.listSession` wire。
- Web 端到端用例增加“首发 Skill 已消失”场景：页面保留规范文本、显示可见失败，随后修正为有效 Skill 可继续发送。

## PTO 插件与业务 Skills：失败分诊纵向切片

### 变更

- `pto_run_inspect` 为五类可选 DFX capability 增加权威 `RunConfig` / pytest 补采 literal；timeline 同时披露开启泳道采集会让 workload 运行两遍。
- 新增独立 `runHealth`：完整 L2 清单未观察到 `passes_dump/`、`ptoas/`、`kernels/` 文件时标为 `incomplete-or-failed`，清单截断或 L3 父 run 保持 `unknown`；同时只列出诊断文件路径，不读取内容或生成原因。
- 新增官方 bundled Skill `pto-debug`，按 compile、runtime、accuracy 与“仅缺性能证据”四类 symptom 分诊，定位首个有证据的失败边界，排序 candidate causes，并提出最小判别动作。
- `pto-debug` 默认只读；不会执行 `debug/run.py`、pytest、编译、设备 workload 或补采，也不会修改源码和生成物。任何执行/修改都需另行授权。

### 设计判断

- “本次未采集”与“运行未完成或失败”必须来自同一工具契约中的不同字段，不能由 Skill 根据文件名临场猜测；上游开关 literal 同样由 Host 代码持有。
- L3 父 run 不具备可靠的 compile-side 完整性结论，因此 Skill 必须先解析并检查相关 `next_levels` 子构建。
- 未采集是可选 DFX 缺失的优先解释，不是原因证明；运行中断也可能造成 DFX 缺失，诊断报告必须保留这个反例。
- 不新增 `/debug` 命令。复杂分诊属于 Skill，底层插件只提供确定性观察与边界。

## PTO 插件与业务 Skills：候选优化实验切片

### 变更

- 新增官方 bundled Skill `pto-optimize`，消费 `pto-analyze` / `pto-debug` 的证据结论，生成带 source/config anchor、作用机制、预期方向、风险、falsifier、验收条件和回滚的候选实验。
- 候选按证据强度、信息增益、实现/复跑成本与回归风险排序；不会把首个候选称为“最佳”或“最优”。
- 实验计划显式记录 workload/input/shape、program/rank scope、hardware/environment、configuration、collection overhead、metric scope/aggregation 与 correctness guard；阈值缺失时保持 `needs-user-confirmation`。
- bundled provider baseline 增加 `pto-optimize` 的未分组、Workspace、PTO origin 与正文加载检查。

### 设计判断

- 当前切片不增加 Host 原语。候选生成属于业务推理；源码 working copy、隔离输出目录、执行事务与 before/after 计算仍需后续确定性工具契约。
- baseline run 是不可修改证据，source workspace 是取得授权后才可修改的对象，environment 是复跑与可比性的独立身份维度；三者不得按目录邻近关系合并。
- `identityStatus=unverified` 或缺少可靠 source/config join 时，只能返回 conceptual action 和身份缺口，不能生成绑定到当前源码的确定性 edit。
- diagnostic run 只因新增 DFX 证据不会成为 candidate。candidate 使用可恢复源码工作副本和新 output directory，不覆盖已有 run。
- `pto-optimize` 当前为 proposal-only：不改文件、不编译、不复跑、不启动设备 workload。复杂优化也不新增 `/optimize` 命令。

## PTO 插件与业务 Skills：Before/After 比较切片

### 变更

- 新增官方 bundled Skill `pto-compare`，要求显式 baseline/candidate role，并在两边 `pto_run_inspect` 后建立 comparison identity。
- identity 覆盖 operator/program/rank、workload/input/shape/dtype、hardware、software/compiler/runtime、collection config/overhead、metric definition/unit、scope/timebase、round/warmup/samples/statistics，以及 source/build lineage 与唯一 candidate change。
- task match 使用 `matched / partial / unmatched / unavailable`；只有完全 matched 且无额外 confounder 时允许 collected delta，其他状态只并列展示两边证据与 mismatch。
- comparison 明确区分 projected、simulated、collected；结果限定为 `supported / not-supported / inconclusive / incomparable`，hard guard 优先于性能改善。
- bundled provider baseline 增加 `pto-compare` 在未分组、Workspace、PTO origin 与正文加载的检查。

### 设计判断

- 本切片不新增 comparison Host tool。run 目录当前没有 canonical comparison manifest，`identityStatus=unverified`；通用工具若只比较 Agent 填入的字符串与数字，无法验证源证据，反而会制造系统已保证可比性的错觉。
- 待 app-owned run registry 与具体 metric adapter 能从 raw artifacts 建立 comparison identity 后，再把 gate、统计与 delta 下沉到 Host code；当前 arithmetic 只能作为带路径与公式的 derived finding。
- relative delta 只在 baseline 非零时计算；没有预设 threshold 与 variance/repetition 规则时，只报告 observed direction，不声称显著改善或回归。
- diagnostic run 只因增加 DFX 证据不会成为 candidate；collection overhead 不兼容会直接阻止因果 delta。
- 不新增 `/compare` 命令。复杂的证据准入与结果解释属于 Skill。

### 验证结果

- `skill-creator` quick validation：当前五个 PTO bundled Skills 全部通过。
- bundled provider baseline 验证 `pto-compare` 在未分组与 Workspace 草稿中均标记为 `PTO`，且完整正文可加载；PTO、DSH 与 Workspace origin 继续隔离。
- 外层与 harness 工作树 `git diff --check` 均通过；本切片没有改变 Host tool schema、Client package 或 profile 装配。
