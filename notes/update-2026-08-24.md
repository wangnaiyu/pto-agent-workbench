### 变更

`harness/packages/client/ui-workspace`：

- Tab「运行历史」改名为「运行记录」（`tabs.runRecords`，en `Run Records`），对齐 `interface-frame-workbench` 的 `运行记录ID` literal；搜索文案同步改为「搜索运行记录」。
- 新增 `src/client/runRecords.ts`：运行记录对象模型与树推导（`OpenedRunRecord` / `RunRecordNode` / `RunRecordGroupNode`），含路径包含判定 `isDescendantPath` 与归属判定 `containingGroupKey`。
- 运行记录树与会话树同构：按已注册工作区分组（Host 顺序）+ 未分组；未分组是**导入桶**，`recordCount` 为 0 时也常驻渲染。
- `＋`（打开运行记录）只挂在未分组组行，hover 显现；工程组行不显示 `＋`，也不提供工作区重命名／删除菜单（那属于会话 Tab 的注册所有权）。
- 标题栏图标组在运行记录 Tab 下只有搜索：无新会话、无视图选项、无 groupBy。
- 折叠栏不承载运行记录：`wide` 变 false 时视图回落到「会话」，并清掉运行记录查询，避免它变成会话过滤词。
- 数据源为「用户显式打开记录的持久化清单」：`stores.ts` 新增 `openedRunRecords` 与 `runGroupExpansion`，persist key `dsh.workspace.view.v5` → `v6`（rehydrate 整体替换 state，新字段必须换 key）。
- 移除只摘登记：`removeRunRecord` 只删清单条目，确认框写明「目录及其中的文件会原样保留」，照 `workspaceRegistry.delete` 口径。
- 打开流程复用本面 `sidebar.workspaces.directoryFlow` 唯一占位者：`WorkspacePickFlow` 新增 `adoptPath`，运行记录路径下不调用 `createWorkspace`（延迟注册），失败仍进同一个可重试的文件夹错误弹窗。
- 行为定位：run 行是回溯与挑选对象，不是任务起点——行本身不可点击（`cursor: default`），只保留 hover 卡片（名称 + 完整路径 + 复制）与 `...` 菜单。

### 重要判断 / 决策

- **归属判定采用「打开时一次性判定 + 黏性」**。§1 写「canonical path 的父目录命中已注册工作区则归该工程组」，§2 又写「先开独立 run、后加父工程时独立 run 的卡片保留在未分组，两张卡产出的会话按各自 cwd 归属」。二者只有在「归属在打开那一刻判定并固化」下才自洽：打开时命中最内层已注册工作区则进该工程组，否则进导入桶；此后再注册父工程不迁移该行，父工程自己的扫描会把同一目录作为它自己的行呈现。已在 `runRecords.ts` 模块文档与测试中固定该语义。
- **路径只作 opaque locator**：作为行 id、显示名与交给消费方的值，不参与除打开时包含判定以外的任何语义 key（遵 §7 接缝规矩）。
- **`project` 字段收敛**：group node 用 `project: { workspaceId, cwd, createdAt } | undefined` 表示「有无backing workspace」，取代三个各自可空的字段，导入桶与工程分节由此成为一个判定。
- **工程组下暂为空**：按需扫盘属于 §7 发现层 host 插件，本轮范围外（用户确认只做侧边栏 IA + 显式打开清单）。
