### 重要判断 / 决策

- **归属判定采用「打开时一次性判定 + 黏性」**。§1 写「canonical path 的父目录命中已注册工作区则归该工程组」，§2 又写「先开独立 run、后加父工程时独立 run 的卡片保留在未分组，两张卡产出的会话按各自 cwd 归属」。二者只有在「归属在打开那一刻判定并固化」下才自洽：打开时命中最内层已注册工作区则进该工程组，否则进导入桶；此后再注册父工程不迁移该行，父工程自己的扫描会把同一目录作为它自己的行呈现。已在 `runRecords.ts` 模块文档与测试中固定该语义。
- **路径只作 opaque locator**：作为行 id、显示名与交给消费方的值，不参与除打开时包含判定以外的任何语义 key（遵 §7 接缝规矩）。
- **`project` 字段收敛**：group node 用 `project: { workspaceId, cwd, createdAt } | undefined` 表示「有无backing workspace」，取代三个各自可空的字段，导入桶与工程分节由此成为一个判定。
- **工程组下暂为空**：按需扫盘属于 §7 发现层 host 插件，本轮范围外（用户确认只做侧边栏 IA + 显式打开清单）。

## 会话未分组常驻与空态归组

### 变更

- `ui-workspace/tree.ts` 无论可见未归属会话数量是否为 0，都在已注册工作区之后追加未分组；空白占位会话失去当前选中后仍隐藏自身，但不再带走组头。
- 分组模式的「暂无会话」收入未分组 section，只要未分组展开且自身为空就显示，不受其他 Workspace 分组是否有会话影响；平铺模式保持原有全局空态。
- 所有会话分组（含未分组）的文件夹图标统一：仅在「分组展开且包含当前会话」时使用 business primary 状态色；只有展开、没有当前会话时仍使用三级标签色。

## 未分组会话的 default 持久化桶

### 变更

- JSONL 持久化后端新增可选 `projectDirectoryAliases`，可将选定真实 cwd 映射到 `root` 下的安全字面目录；Session header 的绝对 cwd 不变。
- 工作台 `patches/cordis.patch.yml` 将 Host 进程 cwd 映射为 `default`，因此新实体化的未分组会话落在 `~/.dsh-pto-workbench/sessions/default/<session-id>/session.jsonl.zstd`。
- `start.sh` 在 app 参数之前传入 `--patch`，确保 3180 正式启动路径使用该配置。
- 旧会话不自动搬迁：启用别名后仍可从原 cwd 编码目录恢复，后续追加保持在原位；新会话使用 `default`。

### R1 理由

这是物理持久化寻址能力，只有 `session-persistence-jsonl` seam 拥有日志路径、身份校验和旧产物恢复的完整上下文。在 Host 或 client 插件中伪造 cwd 会同时改变工具执行目录和 UI 语义，因此采用最小后端配置扩展，并由工作台静态 patch 启用；通用 DSH profile 不受影响。

### 验证

- JSONL 定向测试：154 个用例通过（含别名寻址、真实 cwd 保留、普通 cwd 不受影响、旧目录兼容、非安全／重复别名拒绝）。
- 定向 TypeScript 检查、oxlint、全量 `pnpm run build` 通过。
- `--dump-config` 显示工作台 patch 已覆盖 `session-persistence-jsonl` 并包含 `cwd: !!js process.cwd()` → `directory: default`。
- `pnpm run doc-sync`：28 项通过、0 失败。
