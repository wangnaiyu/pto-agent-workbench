# update-2026-08-26

## 新会话输入框 `+` 的草稿能力目录：Host 静态目录

### 变更

- 新增 `harness/packages/host/composer-catalog`，提供只读 Remote `composerCatalog.listDraft({ workspaceId?, agentPreset? })`，并装配进 Web Host bundle 与 Client Remote facade。
- 命令注册定义新增可选技术 `provider`；`listDiscoveryForScope()` 返回最终 winner 的 descriptor、`global | scoped` layer 与 provider，不把 handler、scope key 或内部路径放进 wire。
- Host 目录按可信 `providerOrigins` 配置投影 `DSH`、`Agent`、`PTO`、`User`、Workspace 名称和插件名称；未知插件降级为 `Plugin`。
- Skill 目录只保留 `userInvocable` winner，同时返回 `modelInvocable`；默认顺序为 User、PTO、Workspace、DSH、Plugin，再按来源标签与名称稳定排序。
- 未分组查询使用真正的 `cwd: undefined` 并过滤 project source；Workspace 查询由 Host 注册表解析路径和显示名称，并可读取 preset 隔离 realm 的 Skills service。
- 响应包含内容哈希 `revision` 与局部错误；description 在 Host 侧限制为 1000 字符。首版不发送图标内容，只保留可选 `iconId` 协议位置。

### 边界与判断

- 本阶段只建立 Host 静态事实源，不实现 Client 菜单、`/skill <name>` 语法或首次发送再校验。
- `bundled` 继续只是技术来源，不自动等于 PTO；下一阶段由 PTO profile/provider 显式把本仓库 `skills/` 声明为 `PTO`。
- 当前 Skill registry 对 provider 失败只暴露 `complete=false`，因此 seam 能保留成功条目并给出 Skills 区域级局部错误；待底层提供 provider 级诊断后再细化到具体来源标签。
- 静态目录使用内容哈希 revision 满足当前 generation 边界；是否增加推送失效事件留到 Client source 引入真实缓存时决定。

### 验证结果

- `pnpm run build:lib:host` 通过，生成 `composerCatalog.listDraft` Host/Remote artifacts。
- `pnpm run typecheck:contracts-ready` 通过。
- 命令、preset 与 composer catalog 定向回归共 5 个测试文件、115 个用例通过；其中包含真实 Loader/YAML 装配测试。
- Cordis 主目录与文档依赖图生成成功；新增 `CommandDiscoveryEntry` 已进入命令 subsystem 的 type-equiv 与类型链接清单。
- `gen-cordis-inspect-catalog` 仍受既有 `ui-conversation -> @deepseek-ai/dsh-permission-presets/client` cross-face 解析问题阻塞；该问题在上一阶段已经存在，与 composer catalog wire 无关，需单独修复。

### 后续动作

- 启动第三阶段 PTO bundled provider 基线：确定本仓库 `skills/` 的发现根、发行 metadata、`providerOrigins` profile 配置和至少一个最小官方 PTO Skill fixture。

## 新会话输入框 `+` 的草稿能力目录：PTO bundled provider 基线

### 变更

- PTO profile 启用 Host `skill-filesystem` row，使用独立 provider `pto-bundled`、`includeDefaultRoots=false` 和相对 patch `baseUrl` 指向 `skills/bundled/`。
- `composer-catalog.providerOrigins` 显式把 `pto-bundled + bundled` 映射为 `PTO`；没有按 Skill 名称、provider 前缀或通用 `bundled` source 猜测产品来源。
- 新增首个官方业务 Skill `pto-evidence-intake`，用于分析前整理数据等级、share-safe、证据权威性、claim 类型和验证状态；它不替代分析工具或伪造运行结论。
- 新增 `experiments/pto-bundled-skill-baseline/run-check.ts`，以真实文件系统 provider 和真实 `composerCatalog.listDraft()` 验证来源与范围矩阵。

### Skill 设计影响

- 按 `skill-creator` 保持单文件、窄触发和渐进披露；当前流程不需要 scripts、references、assets 或额外 UI metadata。
- DSH 在调用字段缺省时默认 `userInvocable=true`、`modelInvocable=true`。为兼容通用 Skill frontmatter 校验，不写 DSH 专有 `user-invocable` 字段，调用语义不变。
- Skill 沿用 PyPTOUX 的 L1/L2/L3、share-safe、上游 literal 和 claim verification 约束，但不复制 source registry，也不修改只读 PyPTOUX mirror。

### 验证结果

- `skill-creator/scripts/quick_validate.py`：`pto-evidence-intake` 通过。
- `dsh web --patch patches/cordis.patch.yml --dump-config`：确认 `pto-bundled` root 和 PTO `providerOrigins` 进入最终 composed config。
- 真实 provider/catalog 检查：未分组返回 `pto-evidence-intake -> PTO` 与控制项 `dsh-helper -> DSH`，不泄漏 project Skill；Workspace 草稿额外返回 `project-helper -> Phase 3 Workspace`，PTO 与 DSH 标签保持不变，完整 PTO Skill 正文可加载。
- 使用临时 `DSH_HOME` 和随机端口完整启动 Web profile 成功，随后主动停止；证明 patch 表达式与 Loader 装配可激活。

## 新会话输入框 `+` 的草稿能力目录：Client 统一 source

### 变更

- 新增 `harness/packages/client/ui-composer-catalog`，以草稿专用 `/` source 调用 `composerCatalog.listDraft`，Commands 放在无标题第一部分，Skills 放在带 `Skills` 标题的第二部分。
- `ui-input-trigger` 从仅 Session controller 扩展为显式 Session/draft target；旧 source 缺省仍仅支持 Session，不会被误暴露到草稿。
- 新会话驻留输入机绑定唯一 draft controller；键入 `/` 与前置 `+` 共用菜单、键盘仲裁、span-CAS 和 pick 路径，全程不创建 Session。
- Workspace 和 Agent preset 的草稿选择都进入 target identity；切换只关闭旧菜单和使缓存失效，不重置文本。
- 菜单行固定为预留图标位、名称、最多 80 字符且显式 `...` 的描述、最右来源；完整描述与来源保留在 tooltip/accessible label。搜索匹配名称、描述与来源。
- 传输失败保留可重试 source 行；Host 局部错误与成功条目共存，重试只重拉该 source，不隐藏成功 sibling。Host 重连清空 Client 目录缓存。
- 选择 Command 只插入 `/<name> `，选择 Skill 只插入预留语法 `/skill <name> `；同名项在两个分区都保留。本阶段未实现 Host 发送解析。
