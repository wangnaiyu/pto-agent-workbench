# decision-2026-08-25

## 新会话输入框 `+` 的草稿能力目录

> 本分区 `owner: Codex`、`source: user`、`status: accepted`、`decision: accepted`。

### 背景

输入框左下角的 `+` 需要在尚未创建 Session 的新会话草稿中展示可调用能力，同时继续遵守“首次发送才持久化”的既有约束：点击新会话入口、点击 `+`、打开菜单或选择菜单项，都不能分配 `sessionId`、恢复 Agent 或写入会话文件。

新会话有两种来源：

- Workspace 分组：草稿已经暂存 `workspaceId`、解析后的 `cwd` 和所选或默认 `agentPreset`。
- 未分组组别：草稿不传 `workspaceId`，最终工作目录由 Host 在首次发送时解析；UI 使用 `default` 表达该状态。

### 术语和能力边界

DSH 没有与 `.agents/skills` 对等的 Workspace `agent commands` 文件目录。命令由 Host 插件注册，可能位于全局层，也可能位于 Agent preset 的 standing scope；Workspace 文件系统提供的是 Skills。

本功能统一使用以下产品术语：

- **通用命令**：Host 命令注册表全局层中的用户可发现命令。列表必须来自运行时注册表，不能在客户端硬编码。
- **当前 Agent 命令**：新会话草稿所选或默认 Agent preset 的 standing scope 相对全局层新增或覆盖的命令。它不是 Workspace 文件，但按产品策略只在 Workspace 新会话中展示。
- **项目 Skills**：对目标 Workspace 解析后最终生效、允许用户主动调用，且 `source` 为 `project-dsh` 或 `project-agents` 的 Skills，即分别来自项目根下 `.dsh/skills` 和 `.agents/skills`。

用户级、bundled、custom root、runtime 等来源的 Skills 不进入“项目 Skills”。未分组草稿不得因为 Host cwd 恰好位于某个仓库而扫描或展示该仓库的项目 Skills。

### 已接受的范围矩阵

| 新会话来源 | 通用命令 | 当前 Agent 命令 | 项目 Skills |
|---|---:|---:|---:|
| Workspace 分组 | 显示 | 显示，有则出现 | 显示，有则出现 |
| 未分组组别 | 显示 | 不解析、不显示 | 不扫描、不显示 |

未分组只展示通用命令是明确的产品隔离策略，不代表这些 Agent 命令或 Skills 在 Host cwd 上一定不存在。

### 用户体验决策

1. 点击输入框左下角 `+` 立即打开能力菜单，不再只向输入框机械插入 `/`。
2. Workspace 草稿按“通用命令”“当前 Agent 命令”“项目 Skills”分区展示；空分区隐藏。未分组草稿仅展示“通用命令”。
3. 点击 `+` 与手动输入 `/` 使用同一份草稿能力目录、同一套搜索和排序，不能产生两套结果。
4. 选择命令或 Skill 只把调用文本填入输入框，不执行能力、不创建 Session。命令按其参数提示插入 `/name` 或 `/name `；Skill 插入 `/name `。
5. 菜单提供跨分区过滤；匹配结果保留分区来源。菜单底部显示弱提示：“选择后填入输入框，发送后才创建会话。”
6. Agent 命令覆盖同名通用命令时只显示一次，归入“当前 Agent 命令”。命令与 Skill 同名时遵循现有运行语义：命令优先，同名 Skill 不展示。
7. 通用命令与 Workspace 附加能力分开加载。Workspace 能力加载失败不能移除通用命令；对应分区显示可重试的错误状态，不能静默消失。
8. Workspace、Agent preset 或草稿 revision 变化时，立即关闭旧菜单、取消或忽略旧请求，并按新目标重新加载，避免把旧 Workspace 的能力填入新草稿。
9. 菜单不展示本地绝对路径、provider 内部标识或原始注册作用域。项目 Skill 可使用轻量的“项目 Skill”来源标记帮助用户识别 Workspace 内容。
10. 第一阶段不尝试在无 Session 状态下直接打开依赖 Session 的命令弹窗。选择这类命令仍然只填入调用文本；模型、权限等已经存在的草稿安全控件继续由输入框工具栏负责。

### 首次发送生命周期

首次发送是唯一的持久化边界：

1. 用户创建 Workspace 或未分组草稿，此时没有 Session。
2. 客户端请求草稿能力目录；查询只能读取注册表和 Skill 元数据。
3. 用户选择条目后，客户端只更新输入框文本。
4. 用户发送时，客户端按既有流程创建 Session，并应用草稿中的 Workspace、Agent preset、模型和权限等配置。
5. 客户端或 Host 使用正式 Session 的最终能力目录重新校验调用名称及优先级。
6. 校验成功后再执行命令或注入 Skill；若能力已经消失、来源改变或冲突结果变化，则保留草稿文本并给出明确错误，不得静默降级为普通模型提示词。

打开菜单、过滤、重试加载和选择条目均不得触发上述第 4 步。

### Host 端设计

新增一个面向草稿的只读能力目录 seam。建议协议命名为：

```ts
composerCatalog.listDraft({
  workspaceId?: WorkspaceId
  agentPreset?: string
}): Promise<DraftComposerCatalog>
```

建议响应结构：

```ts
interface DraftComposerCatalog {
  revision: string
  globalCommands: CommandDescriptor[]
  agentCommands: CommandDescriptor[]
  projectSkills: DraftSkillDescriptor[]
  partialErrors?: Array<{
    section: "agentCommands" | "projectSkills"
    code: string
    message: string
  }>
}
```

协议不接收客户端提供的原始 `cwd`。传入 `workspaceId` 时必须由 Host 的 Workspace 注册表解析可信工作目录；未传 `workspaceId` 时直接走“仅全局命令”路径，不得读取 Host cwd 的 Skills。

#### 命令解析

- 为命令运行时增加只读的全局描述符查询能力，例如 `listGlobalDescriptors()`。
- 增加按 standing scope 读取有效命令的内部能力，例如 `listForScope(scopeKey)`；该方法不能要求构造 Agent。
- Workspace 草稿通过 `agentPreset` 对应的 standing scope 得到有效命令视图，再与全局视图比较：新增项及同名覆盖项进入 `agentCommands`，未被覆盖的全局项进入 `globalCommands`。
- 未分组草稿不解析 Agent standing scope，只返回全局层。
- 所有结果均来自实际注册表，不维护内置命令白名单。

#### Skills 解析

- 仅 Workspace 草稿解析 Skills。
- 用 Host 解析出的 Workspace `cwd` 和 Agent preset standing scope 读取最终有效 Skill 视图，以保留 preset 作用域覆盖语义。
- 只保留 `userInvocable !== false` 且 `source` 为 `project-dsh` 或 `project-agents` 的条目。
- 如果 Agent preset 使用隔离的 Skills 服务，应给 preset 服务增加不创建 Agent 的 standing-scope 服务解析入口；不能退回根服务而改变实际执行语义。
- 在 Host 端完成命令/Skill 同名冲突裁决，再返回客户端。

#### 数据最小化与错误隔离

- Skill wire descriptor 只包含展示和调用所需字段，不暴露绝对文件路径、完整 frontmatter 或内部 provider 对象。
- 全局命令查询成功、Agent 命令或 Skills 查询失败时，响应通过 `partialErrors` 返回局部错误，保留其余分区。
- 不存在或已删除的 `workspaceId` 返回明确的目标失效错误；客户端应关闭菜单并提示用户重新选择 Workspace。
- 目录查询不得调用 Session create/resume，不得产生 session header，不得写入 `~/.dsh*` 会话数据。

### 客户端设计

现有输入触发器以 `sessionId` 为唯一目标，需扩展为 Session 与草稿并列的显式目标：

```ts
type InputTarget =
  | { kind: "session"; sessionId: string }
  | {
      kind: "draft"
      draftRevision: string
      workspaceId?: WorkspaceId
      agentPreset?: string
    }
```

实现要求：

- 新增草稿目录 source，将 `composerCatalog.listDraft` 的三个数组投影成现有菜单分区；不要让 `ui-commands` 直接依赖 `ui-skill` 后在浏览器自行拼接两套远端 API。
- 草稿 source 同时服务 `+` 点击和 `/` 输入触发。
- Session 创建完成后，输入目标从 `draft` 原子切换为 `session`，后续继续使用现有 Session 命令和 Skill 目录。
- 以 `draftRevision` 防止迟到响应污染新草稿；Workspace 或 Agent preset 切换必须产生新 revision。
- 通用命令分区可以先显示，Agent 命令和项目 Skills 允许显示独立加载态。
- 未分组请求和 UI 投影都应结构性地缺少 Workspace 附加分区，而不是仅在渲染层隐藏已经扫描出的结果。

### 缓存与失效

草稿目录可按 `{workspaceId?, agentPreset?, commandGeneration, skillGeneration}` 缓存，但缓存不能改变隔离规则。

以下事件必须使相关缓存失效：

- 命令注册表 `commands/change`。
- Skill provider 的 `skills/change` 或文件系统失效通知。
- Workspace 更新、删除或路径变化。
- Agent preset 变化。
- 草稿 revision 变化或草稿被丢弃。
- Host 重连、profile 重载或运行时 generation 变化。

如果现有 `skills/change` 尚未转发给浏览器，应由草稿目录 seam 自己产生合并后的 revision 或失效事件，避免客户端监听底层 provider 细节。

### 包边界与改造优先级

按工程 R1，先用动态插件 spike 验证“无 Session 读取全局命令、standing-scope 命令和项目 Skills”的完整回路，再固化为静态 Host/Client 插件。

现有命令服务没有公开全局层或 standing scope 的描述符读取能力，纯插件无法可靠完成目录分类。因此允许做最小内核扩展：只增加只读查询和 standing-scope 服务解析，不增加草稿执行、不改变 Session 创建语义。协议适配、来源过滤、冲突裁决、缓存与 UI 均保留在插件或边缘 package 中。

### 不采用的方案

- **为目录查询临时创建 Session**：违反首次发送才持久化，也会制造空会话条目和磁盘数据。
- **客户端硬编码通用命令**：无法反映 profile、插件、权限及运行时变化，必然与真实可执行目录漂移。
- **客户端扫描 `.agents/commands`**：DSH 没有该官方命令格式；会虚构一套与 Host 命令注册表无关的能力体系。
- **分别调用 Session command API 和 skill API 再由客户端合并**：草稿没有 `sessionId`，且会把来源过滤、作用域覆盖和冲突语义复制到客户端。
- **未分组按 Host cwd 加载项目 Skills**：会再次把工作台安装目录或启动目录误认为用户选择的 Workspace，破坏 `default` 的产品含义。
- **选择菜单项时立即执行**：命令执行需要正式 Agent/Session，会提前跨越持久化边界。

### 分阶段实施

1. **动态 spike**：证明不创建 Session 也能读取全局命令、指定 preset standing scope 命令和指定 Workspace 项目 Skills；记录 Session 数量及磁盘写入基线。
2. **Host 静态能力目录**：补最小只读服务 seam、`composerCatalog.listDraft`、来源过滤、冲突裁决、partial error 和 generation。
3. **客户端草稿 source**：扩展输入目标，接入 `+` 与 `/`，实现分区、搜索、加载、重试和 revision 竞态保护。
4. **首次发送再校验**：复用正式 Session 目录，补能力消失和冲突变化的错误处理。
5. **集成与回归**：覆盖 Workspace、未分组、Agent preset 切换、Host 重连及会话持久化边界。

### 验收与测试矩阵

#### Host 单元与集成测试

- 未传 `workspaceId` 时只返回全局命令，且不调用 Workspace Skill 解析。
- 传入 Workspace 时正确分类全局命令、Agent 新增命令和 Agent 覆盖命令。
- 只返回 `project-dsh`、`project-agents` 且用户可调用的最终 Skill。
- 命令与 Skill 同名时命令优先；Agent 同名命令覆盖全局命令且只返回一次。
- preset 隔离服务与根服务不同时，草稿结果和正式 Session 结果一致。
- Skill 查询失败只产生局部错误，通用命令仍可用。
- 无效 Workspace 不接受客户端路径回退。
- 每次 `listDraft` 前后 Session 数、Agent 恢复数和会话文件数保持不变。

#### 客户端测试

- Workspace 草稿出现三个约定分区，空分区隐藏。
- 未分组草稿始终只出现通用命令。
- 点击 `+` 与输入 `/` 的过滤结果一致。
- 选择条目只修改输入文本，不创建侧边栏条目或 Session。
- Workspace 附加目录失败时通用命令仍显示，并有可重试错误状态。
- 快速切换 Workspace 或 preset 时，迟到响应不会覆盖新草稿。
- 首次发送成功后才出现正式会话入口，并切换到 Session 目录。
- 首次发送时能力失效会保留输入并提示，不会当普通消息发送。

#### 端到端验收

- 从 Workspace 组行 `+` 创建草稿，能看到通用命令、该 preset 的 Agent 命令及该项目 Skills。
- 从未分组组行 `+` 创建草稿，即使 Host cwd 位于 `pto-agent-workbench`，也只显示通用命令。
- 仅打开和使用菜单后，侧边栏、Session API 以及本地会话存储均无新增记录。
- 首次发送后只生成一个 Session，最终 `cwd`、侧边栏归组和能力执行结果一致。

### 完成定义

只有在以下条件同时满足时，本决策视为实现完成：

- 两种草稿来源严格符合范围矩阵。
- `+` 与 `/` 共用目录，选择操作不持久化。
- 目录内容来自运行时注册表和正式 Skill registry，而非客户端硬编码或非官方目录扫描。
- 首次发送前后能力语义经过重新校验。
- 自动化测试能证明目录查询不会创建 Session 或会话文件。
- 用户可从 UI 清楚区分通用命令、当前 Agent 命令和项目 Skills，且未分组不会暴露 Host cwd 的项目能力。
